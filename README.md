# parser — сборщик данных с WordPress-сайтов

Скачивает записи с любого WordPress-сайта через REST API и превращает их
в датасет для LLM (jsonl / json / csv / markdown).

**Сайта по умолчанию нет** — адрес всегда указывается явно.

## Быстрый старт

```bash
# 1. Установить зависимости
python3 -m venv .venv            # или: uv venv --seed .venv
.venv/bin/pip install -r requirements.txt

# 2. Запустить приложение
.venv/bin/python app.py
```

## Приложение (app.py) — основной способ работы

```
╔══════════════════════════════════════╗
║   СБОР ДАННЫХ С WORDPRESS-САЙТОВ      ║
╚══════════════════════════════════════╝

  🚀  Новый сбор          Указать сайт, типы записей и запустить
  🔄  Догрузить новые     Инкрементально: только новые записи
  🏷  Типы на сайте      Посмотреть доступные типы записей
  📁  Профили сайтов      Сохранить, загрузить или удалить настройки
  ⚙  Настройки           Задержка, таймаут, повторы, User-Agent
  📊  Мои датасеты        Что скачано: размер и предпросмотр
  ❓  Помощь              Как этим пользоваться
  ✕  Выход               Закрыть приложение
```

**Новый сбор** — форма, где всё в одном экране:

| Поле | Что делает |
|---|---|
| Сайт | адрес + кнопка «Проверить» |
| Профиль сайта | сохранённые настройки сайта |
| Типы записей | вручную или кнопкой «Определить» с сайта |
| Куда сохранить | имя файла, по умолчанию `<домен>_dataset.jsonl` |
| Формат | jsonl / json / csv / md |
| Лимит записей | пусто = без ограничения |
| Пауза, таймаут | вежливость к сайту |

Кнопки **«Собрать»** (реальный сбор) и **«Проверить всё»** (покажет, что
будет скачано, но ничего не сохранит). Лог идёт прямо в окне.

**Горячие клавиши:** `F2` — новый сбор, `F3` — догрузить, `F8` — датасеты,
`Esc` — назад, `Ctrl+C` — выход.

## Командная строка (parser.py) — для скриптов и cron

```bash
python parser.py https://example.ru                      # posts + pages
python parser.py https://example.ru --list-types          # какие типы есть
python parser.py https://example.ru --types posts,products --max 100
python parser.py https://example.ru --since 2026-01-01    # только свежее
python parser.py https://example.ru --format md --out site.md
python parser.py https://example.ru --incremental --state .state/site.json
python parser.py https://example.ru --profile mysite      # настройки сайта
```

### Все ключи CLI

| Ключ | Что делает |
|---|---|
| `--types posts,pages` | какие типы записей собирать |
| `--list-types` | показать доступные типы записей |
| `--max 100` | ограничить количество записей |
| `--since 2026-01-01` | только записи после даты |
| `--incremental --state файл` | догружать только новые записи |
| `--format jsonl\|json\|csv\|md` | формат вывода |
| `--out -o файл` | куда сохранять |
| `--append` | дописать в существующий файл |
| `--delay 1.0` | пауза между запросами |
| `--retries 3`, `--timeout 30` | устойчивость к обрывам |
| `--per-page 100` | размер страницы API |
| `--user-agent "..."` | свой User-Agent |
| `--keep-html` | сохранять исходный HTML |
| `--no-taxonomy` | не разворачивать id категорий/тегов |
| `--profile имя` | настройки сайта в `sites/<имя>.json` |
| `--save-config файл` | сохранить настройки запуска |
| `--quiet -q` | без прогресса |

## Как это работает

1. **Находит REST API** — пробует `/wp-json/`, `/?rest_route=/`,
   `/index.php?rest_route=/`, а если не вышло — конкретные эндпоинты.
2. **Определяет типы записей** через `/wp-json/wp/v2/types` — не только
   `posts`/`pages`, но и `products`, `news`, любые кастомные.
3. **Обходит пагинацию** — по заголовкам `X-WP-TotalPages`, а если их нет —
   ловит `rest_post_invalid_page_number`.
4. **Чистит HTML** — выкидывает скрипты и стили; inline-теги не рвут
   предложения переносами; блоки разделяются пустой строкой. В формате `md`
   сохраняются заголовки, списки и ссылки.
5. **Разворачивает таксономию** — вместо `categories: [3, 5]` будет
   `category_names: ["Новости", "Статьи"]`.
6. **Пишет атомарно** — сначала во временный файл, потом переименование.
   Если скрипт упал или был прерван — старый датасет останется целым,
   а предыдущая версия сохранится рядом как `.bak`.

## Инкрементальный сбор

```bash
python parser.py https://example.ru \
    --types posts \
    --incremental \
    --state .state/example.ru.json \
    --out example.ru.jsonl
```

Скрипт запомнит максимальный id и при следующем запуске скачает только новые
записи. Если новых нет — скажет об этом и **файл не тронет**. В приложении
то же самое — пункт меню «Догрузить новые».

## Важно

* **Если сайт упал — датасет не пострадает.** Скрипт закончит работу с
  ненулевым кодом возврата и не тронет существующий файл.
* По умолчанию между запросами пауза 0.5 с — не перегружай чужие сайты.
* Некоторые сайты закрыты WAF и отвечают `447` на «бот»-User-Agent —
  помогает `--user-agent` с обычным браузерным UA.
* Проверить API вручную: `curl -s https://example.ru/wp-json/ | head`.

## Структура

```
app.py          — приложение (TUI-меню)
parser.py       — CLI для скриптов и cron
wp_scraper.py   — клиент WP REST API, очистка HTML, сохранение
requirements.txt — зависимости
sites/          — профили сайтов (создаётся автоматически)
```
