# parser — сборщик данных с WordPress-сайтов

Скрипт скачивает записи с любого WordPress-сайта через REST API и превращает их
в датасет для LLM (jsonl / json / csv / markdown).

**Сайта по умолчанию нет** — адрес всегда указывается явно.

## Установка

```bash
python3 -m venv .venv          # или: uv venv --seed .venv
.venv/bin/pip install -r requirements.txt
```

## Быстрый старт

```bash
# интерактивно: спросит адрес, типы, куда сохранить
python start.py

# или сразу адрес в аргументе
python parser.py https://example.ru

# посмотреть, какие типы записей есть на сайте
python parser.py https://example.ru --list-types

# конкретные типы и ограничение
python parser.py https://example.ru --types posts,products --max 100
```

`python start.py https://example.ru --types posts --max 100`

## Все возможности parser.py

| Ключ | Что делает |
|---|---|
| `--types posts,pages` | какие типы записей собирать (по умолчанию posts+pages) |
| `--list-types` | показать доступные типы записей на сайте |
| `--max 100` | ограничить количество записей |
| `--since 2026-01-01` | только записи после даты |
| `--incremental --state файл` | догружать только новые записи (по id) |
| `--format jsonl\|json\|csv\|md` | формат вывода |
| `--out -o файл` | куда сохранять (по умолчанию `<домен>_dataset.jsonl`) |
| `--append` | дописать в существующий файл, не перезаписывать |
| `--delay 1.0` | пауза между запросами (не долбить сайт) |
| `--retries 3` | сколько повторов при обрыве сети |
| `--timeout 30` | таймаут ответа, сек |
| `--per-page 100` | размер страницы API |
| `--user-agent "..."` | свой User-Agent |
| `--keep-html` | сохранять исходный HTML рядом с текстом |
| `--no-taxonomy` | не разворачивать id категорий/тегов в названия |
| `--profile имя` | настройки сайта в `sites/<имя>.json` (создаётся сама) |
| `--save-config файл` | сохранить настройки запуска в JSON |
| `--quiet -q` | без прогресса |

## Как это работает

1. **Находит REST API** — пробует `/wp-json/`, `/?rest_route=/`, `/index.php?rest_route=/`,
   а если не вышло — конкретные эндпоинты `/wp-json/wp/v2/posts`.
2. **Определяет типы записей** через `/wp-json/wp/v2/types` — это не только
   `posts`/`pages`, но и `products`, `news`, любые кастомные типы.
3. **Обходит пагинацию** — ориентируется на заголовки `X-WP-TotalPages`,
   а если их нет — ловит `rest_post_invalid_page_number`.
4. **Чистит HTML** — выкидывает скрипты, стили, формы; inline-теги не рвут
   предложения переносами; блоки разделяются пустой строкой.
5. **Разворачивает таксономию** — вместо `categories: [3, 5]` будет
   `category_names: ["Новости", "Статьи"]`.
6. **Пишет атомарно** — сначала во временный файл, потом переименование.
   Если скрипт упал или был прерван — старый датасет останется целым,
   а предыдущая версия сохранится рядом как `.bak`.

## Инкрементальный сбор

Не качать каждый раз всё подряд:

```bash
python parser.py https://example.ru \
    --types posts \
    --incremental \
    --state .state/example.ru.json \
    --out example.ru.jsonl
```

Скрипт запомнит максимальный id и при следующем запуске скачает только новые
записи. Если новых нет — скажет об этом и **файл не тронет**.

## Важно

* **Не затирай датасет, если сайт упал.** Если сайт недоступен, скрипт
  закончит работу с ненулевым кодом возврата и не тронет существующий файл.
* По умолчанию между запросами пауза 0.5 с — не перегружай чужие сайты.
* Некоторые сайты закрыты WAF и отвечают `447` на «бот»-User-Agent —
  в таком случае помогает `--user-agent` с обычным браузерным UA.
* Если REST API на сайте закрыт — проверить можно руками:
  `curl -s https://example.ru/wp-json/ | head`.

## Структура

```
start.py         — стартовый файл: спрашивает адрес и запускает сбор
parser.py        — CLI (точка входа, без интерактива)
wp_scraper.py    — клиент WP REST API, очистка HTML, сохранение
requirements.txt — зависимости
sites/           — профили сайтов (создаётся автоматически)
```
